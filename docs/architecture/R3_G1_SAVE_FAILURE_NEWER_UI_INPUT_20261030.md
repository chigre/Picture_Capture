# PC-CQ v1.3.0 G1 — newer UI input during failed PDIC save (2026-10-30)

## Root cause

`protect_app_pdic_commit` and `protect_review_pdic_commit` treated
unchanged source PDIC bytes as sufficient authorization to restore
an earlier in-memory snapshot after a writer exception. Synchronous
Tk callbacks can run while saving. If the user updates an editor or
ReviewWindow `vars` in that interval, the old rollback overwrites
new text, simplified-review cache and flags, despite no PDIC change.

## Fail-first evidence

Test-only [`4cbccfba2a5f3cd429d1d081cf4852f96a9fa405`](https://github.com/chigre/Picture_Capture/commit/4cbccfba2a5f3cd429d1d081cf4852f96a9fa405),
`tests/test_g1_save_failure_newer_ui_input_20261030.py`,
[CI #40943370182](https://github.com/chigre/Picture_Capture/actions/runs/40943370182):
Ubuntu Python3.10/3.13 each had **3 expected failures,
4803 passed, 3 skipped**. Cases expose loss of newer main editor
input, newer ReviewWindow word input and simplified cache/flags, and
newer main canvas input during a ReviewWindow error. Two positive
controls retain rollback when input state remains unchanged.

## Minimal fix

In `proofreading/save_safety.py`:
- `_live_editors_unchanged` checks bound editor/Entry identity,
  count and original text against the pre-save snapshot.
- `_review_vars_state` and `_review_vars_unchanged` also compare
  ReviewWindow word variable ownership and text.
- Both protectors restore snapshot only if same page, exact
  unchanged disk bytes, and unchanged captured input state.
- If any input is newer or uninspectable, do not force older words
  or editor/caches over it. Set `_deferred_save_uncertain` and
  propagate the original write exception. Normal verified-unchanged
  rollback remains supported.

This is intentionally conservative. A synchronous change during
the save may be generated by app logic rather than a human; without
independent provenance the correct decision is quarantine, not
overwrite. It is not a universal version ledger for every field,
a cross-process OS CAS or multi-file power-loss atomicity. No public
UI signature, PDIC/PPP/SECTION schema, original-image X/Y, OCR
arbitration or Undo/Redo record format changes.
