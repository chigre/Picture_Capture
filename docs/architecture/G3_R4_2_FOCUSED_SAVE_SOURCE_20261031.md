# G3 R4.2 — human-edit source ownership at focused PDIC save (2026-10-31)

## Threat and exact source attribution

The prior [crop byte-drift guard](G3_R4_2_CROP_SOURCE_DRIFT_20261031.md) protects display of an asynchronous crop, but the accepted crop's original-image and active-SECTION source was not retained on its subsequent human edit. A same-size image replacement with restored mtime, changed SECTION bytes, removed or newly created SECTION could occur **after the crop was displayed and the human typed, before the 160-ms autosave worker**. The original PDIC writer guards old headwords, exact original X/Y and concurrent PDIC bytes; it did **not** reject an otherwise unchanged PDIC on a different source image/SECTION. Missing evidence from a real filtered row was also not a mandatory save blocker. These are source attribution and persistence-integrity questions, **not an assertion of real OCR errors or human truth labels**.

One failure is absent row provenance; six prove stale image/SECTION/removal saves with or without later same-XY human edits were accepted; one caught a post-PDIC-read external SECTION mutation only through unrelated postwrite PDIC readback error; one proves missing provenance did not block a live filter save. This RED test-only commit is intentionally not an acceptance gate.

## Bounded fix and physical ownership

- Production `1c6ec22930ab64fef94023b05cf57abddcddfacb` extends `proofreading/focused_crop_source_fingerprint.py`: from the *previously accepted* crop snapshot select only original image and active SECTION byte/path/absence witness. Deliberately exclude PDIC from the edit witness, since legitimate proofreading will rewrite its PDIC. `verify_focused_save_source` compares current image and SECTION to those displayed bytes with a fail-closed error; **never invent a new proof of the displayed source at save time**.
- `ui/focused_filter_workflow.py::_apply_filter_batch_payload` binds the accepted in-memory witness to each rendered row. `_queue_focused_change` carries it into pending and snapshot records. For an actual active focused-filter save, the worker **requires the witness for every changed row and preflights all affected pages before the first PDIC write**, then delegates to the existing exact-X/Y writer. Failure routes through the existing generic, path-redacted callback, preserving unsaved work and separately queued later edits, and clears close-on-save.
- `proofreading/focused_pdic_updates.py` checks any supplied image/SECTION witness at entry, **immediately before** `_write_pdic_atomic`, and **after** publication before announcing verified success. Direct legacy callers lacking this optional in-memory field retain their existing writer ABI/PDIC checks; it is the live focused-filter UI worker that enforces mandatory provenance. Existing PDIC word, coordinate, original bytes, eight-field readback and R3 journal guards are unchanged.
- No persisted schema, PDIC/PPP/SECTION format, source XY, OCR-origin record, risk queue default, OCR truth label or disabled experiment setting was modified.

## Guarantees and honest limitations

The new checks are **discrete byte-verified optimistic guards**, not an OS-level cross-file lock/CAS, nor a global atomic transaction across multiple pages. A foreign source mutation after the final prepublication comparison or during PDIC publication cannot always be prevented; the postwrite check detects mismatches and prevents a false success report but never rolls back a possible foreign commit. A multi-page external mutation **between** all-page preflight and later writes still leaves a window for partial commits; the per-page writer re-checks the source before publishing. SHA-256 re-reading large image bytes can add disk I/O at autosave; no real-scan timing guarantee is claimed. The record is synthetic automated E2 only. Human edits remain visible for explicit inspection on uncertainty; do not blindly retry against changed SECTION.
