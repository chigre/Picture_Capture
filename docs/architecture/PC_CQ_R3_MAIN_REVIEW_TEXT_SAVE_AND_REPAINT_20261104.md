## Defects reproduced with synthetic actual production entrypoints

1. **Normal Review save refused after editing a headword.** In `commit_proofread_entries` the old order changed `Entry.word` before capturing editable simplified companion text, so `source_word_conflicts` saw the old companion source_word as a different owner and `commit_review_bundle` refused PDIC+companion publication. Test-only `98cd207c` [CI #41695531672](https://github.com/chigre/PictureCapture/actions/runs/41695531672) observed four independent valid permutations of the same bug. The source fix snapshots simplified inputs against OLD Entry identity and advances the companion source only when precisely matched.
2. **Main text bypass / FocusOut changed model too early.** Shared autosave previously treated clean ReviewWindow as all text saved, although the main Tk buffer could be dirty. Main FocusOut also changed the shared Entry before Review's disk-baseline check; an open review then couldn't save. RED `f45dee83` [CI #41696975713](https://github.com/chigre/PictureCapture/actions/runs/41696975713) demonstrated both main FocusOut cases. New ordinary ReviewWindow/main text bridge checks both views against SAME Entry and stages into a paired R3 transaction; main Save delegates to that owner instead of a competing standalone PDIC rewrite. For an older already-mutated model, a read-only exact XY PDIC source-word and before/after byte check can rebase it safely; different two-view edits are preserved and refused.
3. **Failure not actionable, uncertain save allowed navigation.** A toolbar Save failure could escape Tk and an empty focused queue could be mistaken for a settled write despite `_filter_save_uncertain_pages`. New code returns False with explicit sanitized unsaved-state status, prevents close/navigation and instructs a deliberate PDIC check/retry. Original native exception can carry private file paths/words, so never display it to Tk.
4. **Same-page repaint lost unsaved original words.** `review_workspace_workflow.render_rows` destroyed Tk rows before validating async crop cardinality, and it recreated each variable from `Entry.word` even if unsaved human input existed. New `proofreading/review_pending_text.py` captures pending words only with unique SAME Entry object + frozen rendered baseline, preflights crop count and image availability before destroying children, and refuses repaint on unprovable drift. RED test-only `4ee0b387`/`26ae4833`, GREEN `9645d939`; two further source-drift integration tests `9a55f08a`.
