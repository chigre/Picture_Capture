# LAYOUT 分析过程回放（2026-10-13）

## 使用

在主窗口的“显示设置”中勾选 **查看 LAYOUT 分析过程**。它与“显示Layout”相互独立，不会修改普通画线、PDIC、PPP、项目设置或原始图像。回放窗口提供：

- 阶段下拉框、**上一步 / 下一步**；
- **查看修正前**：切换至已记录的最近一个阶段，而不是重新计算；
- 缩放与“适应宽度”；滚动查看扫描全页；
- 蓝色框：正文行；红色框：词头行；绿色粗框：本阶段新增或角色变化；橙虚框：本阶段被删除的行；绿色细框：栏范围；
- 单击任一物理行，查看其像素位置、first_x、角色及从首次出现到最终阶段的变化历程；
- 页面、项目设置、去噪选项改变时自动重新构造**当前页**的只读回放；关闭即停用监控。

初始化窗口后，显示原始图像，后台对本页另做一次与正式流程相同的 Layout Core 计算。界面仅在回放结束后允许步进。若计算失败，窗口显示错误，不影响原有检测。

## 真实阶段与边界

回放由正常 `layout_composition.infer_composed_physical_page_layout` 与 `layout_core_understanding.understand_layout_core` 中的可选追踪节点产生。每次生成的步骤包括：

1. 原图/共享分析图：去噪来源和统计。若使用插图掩膜，再增加掩膜阶段。
2. 逐页自动参数原始建议：`resolve_page_layout_policy` 的真实 `estimate`（若禁用则明确标识）。
3. 经逐字段开关、Profile anchoring 后实际采用的参数。
4. Page Design 物理行，基础角色。
5. 缩进语义、正文缩进族、视觉一致性、缺失缩进恢复。
6. 符号样本与大字头候选融合、重复大字碎片去除、最终大字复核。
7. 完成版的 Layout Core 行角色和源图坐标。

“查看修正前”按**捕获时刻**回放先前坐标，而不是以最终状态倒推出早期分类。新增/删除通过物理行的 `(栏号, canonical_y0, canonical_y1)` 匹配，不使用可能复用的 Python 对象 `id`。

需要注意：这是 **Layout Core** 回放，不包含后续普通画线 `detect_entries` 里的最终候选/SECTION 过滤，也不是原始图像持久化修改。普通画线中已有的独立 `ordinary_unified_diagnostics` 可以继续检查后续决策；未来可作为第二个时间轴扩展。

## CPU / 内存与数据正确性

- 回放默认关闭，普通检测不创建 trace、不记录中间结果，继续使用原有缓存。
- 开启时重跑一次当前页正式 Layout Core 算法；只保存每阶段的小型数值/行框快照，不保存多份高分辨率 PNG；仅对去噪后及可选插图掩膜后两个有像素变化的节点保留下采样预览。
- 窗口在同一图像和 zoom 档只生成一次相应 `PhotoImage`，切换步骤只绘制 Canvas 叠加物，防止反复解码扫描图。
- 回放在单 worker 线程运行；页面改变时丢弃过期结果，窗口关闭时取消未开始的诊断任务并停止观察。
- **原图坐标**：先走真实 `LayoutTransform.canonical_to_source_point` 转换，Canvas 缩放不反写识别坐标。栏轮廓用上左/下右的可视包络框表达，并非像素级分割掩膜；在弯曲版心的后续版本可接入曲线路径采样。
- 即使检测到某阶段的角色变化，阶段说明只能解释该阶段应用了什么机制；同一行有多个证据时不能据此宣称某一候选是唯一原因。
