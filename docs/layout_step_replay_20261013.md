# LAYOUT 分析过程回放（2026-10-13）

## 使用

在主窗口的“显示设置”中勾选 **查看 LAYOUT 分析过程**。它与“显示Layout”相互独立，不会修改普通画线、PDIC、PPP、项目设置或原始图像。回放窗口提供：

- 阶段下拉框、**上一步 / 下一步**；
- **查看修正前**：切换至已记录的最近一个阶段，而不是重新计算；
- 缩放与“适应宽度”；滚动查看扫描全页；
- 蓝色框：正文行；红色框：词头行；绿色粗框：本阶段新增或角色变化；橙虚框：本阶段被删除的行；绿色细框：栏范围；
- 在符号证据阶段直接显示真实候选锚点；大字头阶段显示检测器的**通过 / 拒绝**矩形候选；点击候选可查看状态和高度比；
- 在缩进分析阶段显示紫色虚线的实测缩进族中心，右栏报告容差及支持行数；
- 单击任一物理行，查看其像素位置、first_x、角色及从首次出现到最终阶段的变化历程；
- 页面、项目设置、去噪选项改变时自动重新构造**当前页**的只读回放；关闭即停用监控。

初始化窗口后，显示原始图像，后台按实际普通画线流程进行一次**只读**计算（含 Layout Core 与下游候选过滤）。界面仅在回放结束后允许步进。若计算失败，窗口显示错误，不影响原有检测。

## 2026-10-13 过程一致性补充（PR #467）

早期版本仅调用 `understand_layout_core()`，因此实际上只有 Layout Core
角色判断，不能代表点击【普通画线】后经过的 Y 精修、【】成对词头恢复、
SECTION 过滤及末端误线清理。本版改为**直接调用真实
`processing.detect_entries(..., debug_trace=...)` 一次**。时间轴接在原有
`_record_ordinary_debug_stage` 的实际计算节点，而不是重构虚构的模拟步骤。

真实步骤顺序：

1. 当前页有效 Project/Profile → 共享分析图去噪；
2. **Layout 前自动插图检测及白化**（开关关/未检出/未通过/已白化均显示，
   包含检测数、头字形保留数、小尺寸拒绝数和每个候选多边形；查看修正前显示去噪图）；
3. 自动版面估计、应用后的参数、物理行及 Layout Core 缩进/角色判定；
4. `layout_role_materialization`：实际转换成画线候选；
5. 条件性大字碎片过滤和全页相干 Y 微调；
6. **`bracketed_headword_recovery`【】词头恢复**：真正的左右【】候选字形及
   成对匹配状态标在原图上（绿色实框=成功配对，黄色虚框=未配对）。
   新增的画线坐标与 `ordinary_bracket_pair` 来源升级分别记录，点击可回溯来源；
   若因非 CJK 或 Profile 开关被跳过，会明确标注“未执行”及原因；
7. Profile/SECTION 区域过滤、最后视觉一致性检查、
   `proven_bracket_body_continuation`【】后正文续行误线过滤、空白行过滤；
8. `final_reading_order`：实际普通画线最终输出（与诊断模式下
   `processing.detect_entries` 一致）。

部分步骤由实际条件控制，例如非 CJK 页面未启用【】恢复，不应伪造一个
“检测失败”步骤。**即使主界面当前设置为 OCR／融合模式**，点击此回放开关
仍会在只读设置副本上模拟【普通画线】按钮临时采用的 `left_edge` 模式，
不会修改原始用户设置；它不宣称自己是 OCR／融合的全过程。

每个前处理预览按真实源图坐标绘制，掩膜通过的多边形为红色实线，
被拒绝的多边形为黄色虚线。进入 Layout 后的步骤继续使用**实际
已去噪/白化**的分析图背景；原图不被修改。普通画线点位红色，新增
或来源升级绿色，已删除的点位橙色叉。所有快照仍只在主动回放时采集，
普通运行的算法、阈值、缓存和 PDIC 保存逻辑不变。

## 真实阶段与边界

回放由正常 `layout_composition.infer_composed_physical_page_layout` 与 `layout_core_understanding.understand_layout_core` 中的可选追踪节点产生。每次生成的步骤包括：

1. 原图/共享分析图：去噪来源和统计。若使用插图掩膜，再增加掩膜阶段。
2. 逐页自动参数原始建议：`resolve_page_layout_policy` 的真实 `estimate`（若禁用则明确标识）。
3. 经逐字段开关、Profile anchoring 后实际采用的参数。
4. Page Design 物理行，基础角色。
5. 缩进语义、正文缩进族、视觉一致性、缺失缩进恢复。
6. 符号样本与大字头候选融合、重复大字碎片去除、最终大字复核。
7. 完成版的 Layout Core 行角色和源图坐标。

“查看修正前”按**捕获时刻**回放先前坐标，而不是以最终状态倒推出早期分类。新增/删除通过物理行的 `(栏号, canonical_y0, canonical_y1)` 匹配，不使用可能复用的 Python 对象 `id`。

**当前实现包括 Layout Core 及后续普通画线候选／SECTION 过滤。** 前述原版的“仅 Layout Core”限制现已解除。原始图像和项目持久化内容仍不被修改；OCR/融合模式的独立判定流程不包含在本时间轴。

## 无明显缩进：物理行之后直接进入视觉阶段（PR #468）

在 Project/Profile 选择 **无明显缩进** 时，物理行检测仍测量行首
X 坐标和每栏的聚类（它是原始几何证据，不等于“检测到词头缩进”）。
例如一栏仅有 1 行位于 471px，它只能视为离群的行首观测。

回放时间轴在「物理行检测」之后**直接进入「符号证据融合」**
及其后的大字头、括号等真正会运行的视觉证据阶段，不再显示：

- 「基础行角色」
- 「缩进语义判定」
- 「正文缩进族调整」
- 「视觉一致性复核」
- 「缺失缩进恢复」

其中后两项在当前生产代码中**仅适用于正文缩进模式**，
对于「无明显缩进」原本立即返回全零结果。现在一并跳过它们
真实的空操作，而不是保留两张看似做了复核的空白回放页面。
有明确词头／正文缩进的项目仍保留原有相关流程。

底层 Page Design 的旧二分法仍可能在临时数据中标记少量
`entry`，但在正式进入独立视觉判断前，程序先执行一次
必需的 **无缩进角色中性化**（全部物理行为初始 `body`，不据
行首 X 作词头判断）。这个内部初始化不是用户可见的推断阶段；
回放也不会把其 `unclassified → body` 误列为「视觉一致性复核」
引发的 140 次角色改变。原始临时标签仅保存在调试快照的
`raw_provisional_role` 字段。

此捷径不会跳过后续真正需要的符号证据、括号【】候选、
大字头证据、重复大字碎片过滤和最终普通画线过滤；
不改变有缩进模式的处理或普通画线最终输出。

## 可调的物理行墨迹投影采样宽度（PR #470）

入口：**设置中心 → 普通画线 → 高级设置（普通画线异常时再展开）
→ 物理行墨迹投影采样宽度**。数值是实际正文栏宽的百分比；
范围 10–100%，默认 **42%**，旧项目不含此参数时亦默认 42%。

此值直接传入真实 Page Design 的 `_leading_width`，影响每栏
用于墨迹投影、短间隙连接、过高墨迹带拆分，以及后续物理行
`first_x` / `anchor_x` 证据采集的图像条带。它不是仅改变
回放框长度的装饰性参数。

原算法有最小采样保护：

`实际采样宽 = min(单栏宽, max(所设比例×单栏宽, 7×参考行高, 96px))`

且仍沿用历史最小 24px 上限裁剪保护。因此低于保护宽度的输入
可能显示出比设置百分比更大的实际比例。例如栏宽 600px、
参考行高 35px、输入 10%，实际约 245px；输入 100% 则必为
完整栏宽。

回放「墨迹投影与短间隙连接」和「过高墨迹带拆分」现在逐栏报告
用户设定百分比、栏总宽、**实际生效**的采样像素和实际百分比。
这便于判断某些右侧正文行是否漏采，或采样太宽导致跨行粘连。

保存通过正常项目 `AppSettings.to_json/from_json`，单独字段
`physical_row_projection_width_percent`；GUI 会拒绝小于 10%、大于
100%、NaN、Infinity 和非数字；不更改 PPP、PDIC、源图与切图宽度。

## Y 位置的前置纠偏与最终核定（PR #469 后续修正）

回放原名「分隔线 Y 坐标统一修正」容易被理解为最终全候选平移。
实际流程中存在几种不同职责，不能混用：

1. **已有 Layout entry 的局部 Y 精修**发生在
   `_ordinary_entries_from_layout_roles`，借助共享
   `refined_layout_entry_y_by_line` 将原物理行顶部移到较安全的留白。
2. **前置 Layout 候选页面级 Y 偏移修正**发生在【】词头恢复前
   （真实 `coherent_separator_y_refinement`）。
   只有多个当前已有的 Layout 候选在图像中同时穿过大字、且所需
   上移量有足够一致性时，才将**当时已存在的 Layout 候选**平移。
   这能改善后续【】候选与 Layout 已有线的邻近匹配及去重；
   因而不能机械地挪到最后再对所有新候选执行同一个偏移。
3. **【】词头与后期视觉补线各自独立定 Y**：括号词头通过
   `safe_gap_above` 找实际印刷留白，后期经验证的大字头也根据
   自身观察定位。将第 2 步的早期 Layout 偏移再应用到这些点，
   可能把已经正确的 Y 坐标移偏。
4. **最终候选 Y 坐标确认（不额外平移）**现在显式出现在
   过滤完成之后、仅阅读顺序排序之前。
   它记录真实幸存画线的 X/Y、来源，以及先前页面级偏移数值；
   此处只读检查，不对最终候选强行批量再移动。

因此，“最终全部画线坐标的核定”确实应在末尾，而
“针对初始 Layout 线的页面级纠偏”必须保留在
后续印刷符号候选匹配之前。回放分别显示这两个阶段，
避免暗示一次 Y 修正已经覆盖未来新增的所有候选。

## 回放窗口未看到新增阶段时的诊断（PR #469）

PR #469 最初的回放窗口在计算完毕后**默认选中最后一个阶段**，
而 Windows Tk 的 `ttk.Combobox` 下拉框默认只展示约十行，
造成用户虽然下载并运行分支，却看不到靠前的投影阶段；
阶段并未被算法省略，只是菜单滚动位置遮住了它们。

现在回放从第 01 步开始，阶段下拉列表的可见高度增加至 28 行。
工具栏新增 **「运行版本／阶段清单」**：列出当前进程实际加载的
`layout_step_replay_ui.py`、`layout_step_trace.py`、
`layout_composition.py`、`layout_physical_indent.py` 和
`dictionary_page_layout_policy.py` 完整路径，以及本页全部阶段的
编号、名称、内部 key、是否采集到新增投影步骤。

若某页出现 `physical_rows` 但既没有
`projection_gap_bridge` 也没有 `projection_tall_split`，
这是**阶段记录不一致**，可以直接复制上述清单排查。正常 PR #469
检测路径不允许悄悄发生这个组合。

注意：下载分支 ZIP 不会自动改变 Windows 旧快捷方式的工作目录；
应在解压的新目录里执行 `run_windows.bat`（源文件入口经
`run.py` 将当前目录的 `src` 插入 sys.path）。不要只更新一个
ZIP 而继续运行旧 Release 的启动器。只有右侧「运行版本／阶段清单」
中报告的模块路径，才是当前进程实际运行的版本。

## 物理行之前的墨迹投影与笔画连接（PR #469）

`物理行检测` 前加入两个可回放节点，它们直接采集自真实
`layout_physical_indent.projection_line_runs`：
   
1. **墨迹投影与短间隙连接**。展示来自每栏**行首采样条带**的
   投影连续墨迹带（查看修正前：灰框），以及短空白扫描行被连接后
   的墨迹带（蓝框）与确实被跨越的间隙（橙色粗框）。
   这里连接的是**垂直方向的投影行段**，没有涂改图像像素，
   也不是针对全页图像进行膨胀、形态学闭运算或八邻域连通域重构。
2. **过高墨迹带拆分与逻辑行恢复**。查看修正前是连接后的原始
   墨迹带；查看修正后绿色框是投影函数真实输出的行段，
   紫色是实际选择的墨迹谷拆分线，黄色虚线是无法根据墨迹谷
   可靠分割时采用的高度约束逻辑槽位。右栏还展示每栏的
   参考行高、采样宽度、投影阈值、允许连接的空白行数、
   原始与连接后墨迹带数、谷值拆分数、备用槽位数、
   被排除的短带数及输出段数。
   
**数据来源不是根据最终物理行重推。** `dictionary_page_layout_policy`
原本会用初始行高、改进的参考行高、最终正文范围做三次真正的
`column_strips`。诊断模式只采集最后一轮、真正传入
`LayoutLine` 生成的行段；避免把初始估计误标为正式物理行。
画出的框是**采样条带坐标**，不能误认为整栏文本框，也不能
把投影输出段数量与后续物理行特征筛选后的数量直接等同。

整张扫描图没有为了新增步骤产生新的全分辨率图片副本；
新数据只是原本计算过程中产生的少量整数坐标与统计数字。
正常（未开启回放）路径不运行这些诊断记录、不修改算法阈值
和投影输出。多栏、正文范围及页面旋转使用实际 Layout
变换映射到原始扫描图坐标。在“无明显缩进”模式下，
这两步仍然运行：物理行检测是**几何**前处理，不属于后面的
缩进语义推断，因此与 PR #468 的跳过逻辑并不矛盾。

## CPU / 内存与数据正确性

- 回放默认关闭，普通检测不创建 trace、不记录中间结果，继续使用原有缓存。
- 开启时调用一次真实的普通画线 `processing.detect_entries` 流程（其中包含 Layout Core）；只保存每阶段的坐标、角色与候选来源快照，不保存多份高分辨率 PNG；仅对去噪后及可选插图掩膜后两个有像素变化的节点保留下采样预览。
- 窗口在同一图像和 zoom 档只生成一次相应 `PhotoImage`，切换步骤只绘制 Canvas 叠加物，防止反复解码扫描图。
- 回放在单 worker 线程运行；页面改变时丢弃过期结果，窗口关闭时取消未开始的诊断任务并停止观察。
- **原图坐标**：先走真实 `LayoutTransform.canonical_to_source_point` 转换，Canvas 缩放不反写识别坐标。栏轮廓用上左/下右的可视包络框表达，并非像素级分割掩膜；在弯曲版心的后续版本可接入曲线路径采样。
- 即使检测到某阶段的角色变化，阶段说明只能解释该阶段应用了什么机制；同一行有多个证据时不能据此宣称某一候选是唯一原因。
